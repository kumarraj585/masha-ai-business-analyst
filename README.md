# MASHA — AI Business Data Analyst

An AI-powered business analytics application that lets users ask natural-language questions about retail sales, products, customers, countries, and business metrics. MASHA combines traditional data analysis, machine-learning forecasting, retrieval-augmented generation (RAG), and a LangChain AI agent in an interactive Streamlit application.

## Overview

MASHA is built around one simple idea: a business user should be able to ask a question in natural language and receive an answer backed by the appropriate data or knowledge source.

Examples:

- "Which 5 products generated the most revenue?"
- "Which country generated the most revenue?"
- "How much revenue did Germany generate?"
- "What is the average order value?"
- "Which month had the highest revenue?"
- "What will our sales be next month?"
- "What does Customer ID mean?"

The agent automatically selects the relevant analysis or RAG tool.

### Sales Forecasting

MASHA includes a Random Forest forecasting pipeline based on daily sales history.

Features include:

- Day of week
- Day of month
- Month
- Year
- 1-day lag
- 7-day lag
- 14-day lag
- 7-day rolling average
- 14-day rolling average

Current model evaluation on the project split:

| Metric |     Result |
| ------ | ---------: |
| MAE    | £11,493.43 |
| RMSE   | £18,273.14 |
| R²     |       0.57 |

The current demonstration forecast is for January 2012:

**Predicted revenue: £1,923,937.75**

Forecasts are estimates generated by the model and are not guaranteed outcomes.

### RAG Knowledge Search

MASHA also answers documentation and dataset-definition questions using a RAG pipeline.

The pipeline includes:

1. Dataset guide document
2. Recursive text chunking
3. Hugging Face embeddings
4. Chroma vector database
5. Similarity retrieval
6. Groq LLM generation using retrieved context

The knowledge base contains information about the Online Retail II dataset, columns, business definitions, currency, and forecasting terminology.

## Dataset

The project uses the **Online Retail II** dataset from the UCI Machine Learning Repository.

The original dataset contains 1,067,371 transaction records covering approximately two years of retail activity.

Main fields include:

- `Invoice`
- `StockCode`
- `Description`
- `Quantity`
- `InvoiceDate`
- `Price`
- `Customer ID`
- `Country`

Project revenue is calculated as:

```text
Revenue = Quantity × Price
```

Prices and revenue are expressed in **GBP (British pounds)**.

Dataset source:
https://archive.ics.uci.edu/dataset/502/online+retail+ii

## Installation

### 1. Clone the repository

```bash
git clone <YOUR_GITHUB_REPOSITORY_URL>
cd AI_DATA_ANALYST
```

### 2. Create/sync the environment

This project uses `uv`.

```bash
uv sync
```

### 3. Configure the Groq API key

Create a `.env` file in the project root:

```env
GROQ_API_KEY=your_groq_api_key_here
```

Do not commit `.env` to GitHub.

### 4. Run MASHA

```bash
uv run streamlit run app.py
```

Open the local Streamlit URL shown in the terminal, typically:

```text
http://localhost:8501
```

## Forecasting Methodology

The forecasting workflow converts transaction-level data into daily revenue.

```text
Transaction data
      ↓
Data cleaning
      ↓
Revenue = Quantity × Price
      ↓
Daily aggregation
      ↓
Lag + rolling + calendar features
      ↓
Random Forest
      ↓
Chronological train/test split
      ↓
MAE / RMSE / R²
      ↓
Recursive next-calendar-month forecast
```

The forecast is aligned to the exact calendar month rather than summing weeks that may cross month boundaries.

## RAG Methodology

```text
Retail knowledge guide
        ↓
RecursiveCharacterTextSplitter
        ↓
Document chunks
        ↓
all-MiniLM-L6-v2 embeddings
        ↓
Chroma vector database
        ↓
Similarity retrieval
        ↓
Relevant context
        ↓
Groq LLM
        ↓
Grounded answer
```

The RAG prompt instructs MASHA to use retrieved context and avoid inventing unsupported information.

## Model Evaluation

The forecasting model is evaluated using a chronological holdout rather than randomly shuffling time-series observations.

Current results:

```text
MAE  = £11,493.43
RMSE = £18,273.14
R²   = 0.57
```

Interpretation:

- **MAE** measures the average absolute prediction error.
- **RMSE** penalizes larger errors more heavily than MAE.
- **R²** indicates the proportion of variance explained by the model on the held-out test period.

The current R² indicates moderate predictive performance; the model should be treated as a forecasting component for decision support rather than a guarantee of future revenue.
